# 常见排障提示

这个文件只覆盖本仓库里高频出现、且适合在开发时快速自查的问题。

## 构建失败

### `ccapi` 相关依赖拉取失败

现象：
- 顶层 CMake 配置阶段卡住或失败

先检查：
- 当前环境是否允许联网
- 是否真的需要整仓构建

建议：
- 如果只是做轻量验证，优先改用 `tests/` 子工程构建
- 如果必须整仓构建，再处理外部依赖或网络问题

### Release 构建行为和预期不一致

先检查：
- 是否通过 `./build_release.sh` 触发
- 是否受 `-march=native`、LTO、fast-math 等选项影响

参考：
- `docs/编译优化指南_compile_optimization.md`
- 顶层 `CMakeLists.txt`

## 配置不生效

先检查：
- 是否修改了真正被启动脚本使用的 `conf/*.yaml`
- 插件 `name`、`library`、`enabled`、`config` 字段是否正确
- 运行目录是否和 `.so` 相对路径假设一致

再检查：
- 配置是标量扁平注入，还是依赖 `_yaml` 完整串由模块自行解析
- 插件顺序是否影响链路，例如风控与订单管理的注册顺序

## 事件链路不通

先做三步：
- 搜事件常量，确认发布点和订阅点都存在
- 看模块总览文档，确认该事件是否属于这条链路
- 检查是否被配置关闭，或上游插件未加载

高频场景：
- 行情未进入策略：检查 replay / ctp / monitor 链路和配置
- 下单请求未发出：检查 strategy / risk / order / trade 的顺序和条件
- 回报未落到持仓：检查 trade / ctp_real / position / portfolio 之间的事件传递

## 运行脚本风险

- 顶层 `run.sh` 默认针对接近实盘的链路，不适合作为随手验证命令
- 若只是确认编译或模块行为，优先使用构建验证、测试 harness 或更小的脚本入口
